# Rivo SWE-bench Verified Evaluation

The Chinese version is the default: [README.md](README.md).

This directory contains the script for running Rivo on [SWE-bench Verified](https://github.com/SWE-bench/SWE-bench). The script supports all 500 Verified instances by default. Use `--instance` or `--limit` to run a smaller sample first.

## Evaluation principle

SWE-bench pairs real GitHub issues with the corresponding historical repository commit. Each instance contains the repository, `base_commit`, problem statement, and the `FAIL_TO_PASS` and `PASS_TO_PASS` test information used for grading. Verified contains the 500 instances that engineers confirmed to be solvable. See the [official dataset guide](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/datasets.md) for the data fields.

Evaluation has two stages:

1. **Patch generation**: create a temporary source checkout at `base_commit` and give the problem statement to Rivo. Each instance uses a unique `rivo --session-id` session; Rivo inspects the code, edits the checkout, and leaves the final implementation. The script extracts the source changes as `model_patch`.
2. **Official grading**: the Docker harness applies `model_patch` in a fixed task environment and runs the tests. The target tests must go from failing to passing, and maintenance tests that originally passed must continue to pass. An instance that meets the requirements is reported as `resolved`. Grading is based on test results; the patch does not need to be textually identical to the official gold patch.

This design separates "can the model perform a real software fix" from "are the host dependencies available": the model works in a temporary checkout, sessions are isolated by explicit IDs, and the official harness reconstructs the repository environment in Docker. See the [official evaluation guide](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/evaluation.md).

## Prerequisites

- Go, Python, and Docker
- A configured Rivo provider, model, and credentials
- The Python `datasets` package
- The SWE-bench CLI
- On ARM machines such as Apple Silicon, a local `swe-bench-tasks` checkout for building task images

Install the SWE-bench CLI and task repository:

```bash
python3 -m venv .venv
source .venv/bin/activate
git clone https://github.com/SWE-bench/SWE-bench.git
cd SWE-bench
pip install -e .
cd ..

git clone --depth 1 https://github.com/SWE-bench/swe-bench-tasks.git
swebench dataset check swe-bench-tasks
deactivate
```

Build Rivo from the repository root:

```bash
go build -o Rivo ./cmd/rivo
```

## The three commands

The script is `bench/standard/main.py`.

### `infer`

Run Rivo only to generate predictions and a cost summary, without starting Docker grading:

```bash
python3 bench/standard/main.py infer \
  --instance sympy__sympy-20590 \
  --rivo Rivo \
  --swebench-venv .venv \
  --output-dir .swebench/runs/sympy-20590
```

Flags:

- `--instance`: instance ID; repeat to select multiple instances
- `--limit`: process only the first N selected instances
- `--rivo`: path to the Rivo executable; if omitted, build from the current checkout
- `--repo-cache`: shared bare repository cache directory, default `.swebench/repos`
- `--output-dir`: directory for predictions, costs, sessions, and per-instance logs
- `--timeout`: per-instance Rivo timeout in seconds, default 1800
- `--keep-checkouts`: keep temporary source checkouts in the output directory for debugging
- `--swebench-venv` / `--venv`: use this venv's Python to load `datasets`

### `eval`

Run the official Docker harness on existing predictions:

```bash
python3 bench/standard/main.py eval \
  --predictions .swebench/runs/sympy-20590/predictions.jsonl \
  --instance sympy__sympy-20590 \
  --task-repo swe-bench-tasks \
  --swebench-venv .venv \
  --run-id rivo-sympy-20590 \
  --workers 1
```

Flags:

- `--predictions`: `predictions.jsonl` generated by `infer`
- `--instance`: grade only the selected instance; repeatable
- `--task-repo`: local `swe-bench-tasks` checkout; required for ARM image builds
- `--run-id`: official grading run ID; use a new ID when grading a different patch
- `--workers`: Docker grading concurrency, default 1
- `--swebench`: SWE-bench CLI executable name or path
- `--swebench-venv` / `--venv`: Python virtual environment containing the SWE-bench CLI
- `--keep-images`: keep the task images built locally in this run; removed by default
- `--reuse-images`: reuse existing local task images; cannot be combined with `--task-repo`

### `all`

Run `infer` first, then `eval`:

```bash
python3 bench/standard/main.py all \
  --instance sympy__sympy-20590 \
  --rivo Rivo \
  --task-repo swe-bench-tasks \
  --swebench-venv .venv \
  --output-dir .swebench/runs/sympy-20590 \
  --run-id rivo-sympy-20590 \
  --workers 1
```

`all` accepts the flags of both `infer` and `eval`: it generates patches and the cost summary first, then invokes the official grader.

## Selecting instances and model settings

Without `--instance` or `--limit`, `infer` and `all` run all 500 Verified instances by default. A full run consumes substantial time, disk space, and API budget; validate the environment with a single instance first.

Repeat `--instance` to select multiple tasks:

```bash
--instance sympy__sympy-20590 \
--instance astropy__astropy-14539
```

Or select the first few instances:

```bash
--limit 2
```

The provider, model, and effort are read from the existing Rivo configuration and environment by default; override them from the command line when needed:

```bash
--provider openai \
--model gpt-5 \
--effort medium
```

`--provider` must be used together with `--model`.

The official harness caches results by `run_id` and `instance_id`. Reusing the same run ID for the same instance may reuse an older result.

## Cost and implementation time

After Rivo finishes an instance, the script locates the session by its explicit session ID and invokes `rivo --cost` to read that session file.

The script fails immediately if the cost output cannot be parsed, contains unknown cost entries, or no matching session is found, avoiding untrustworthy cost totals.

Implementation time uses a monotonic clock. It starts immediately before Rivo `--print` is launched and ends when that Rivo process returns. The following operations are not counted:

- repository cloning and temporary checkout creation
- `rivo --cost` cost accounting
- patch extraction and result-file writes
- Docker harness grading

Per-instance time is written to `rows[].implementation_seconds` in `cost-summary.json`; the total is written to `implementation_seconds_total`.

When `--task-repo` is provided, SWE-bench builds task images locally. After `eval` or `all` finishes, the script removes those instance images by default, keeping only the Docker base layers and shared cache; pass `--keep-images` to retain the images for later evaluations.

## Output files

`infer` writes task artifacts to `--output-dir`; `eval` writes grading logs to the same directory. `--repo-cache` defaults to `repos/` for shared bare repository caches.

```text
.swebench/
├── repos/                         # shared bare repository cache
│   └── sympy_sympy.git
└── runs/                          # outputs for each run
    └── sympy-20590/
        ├── predictions.jsonl      # patch list read by SWE-bench
        ├── cost-summary.json      # cumulative cost and time
        ├── instances/             # artifacts for each instance
        │   └── sympy__sympy-20590/
        │       ├── agent.stdout
        │       ├── agent.stderr
        │       └── session.jsonl  # for reviewing rivo --cost
        ├── checkouts/             # retained only with --keep-checkouts
        └── logs/                  # SWE-bench grading logs
            └── evaluation/
                └── rivo-sympy-20590/
                    ├── run.json
                    ├── results.json
                    └── rivo/
                        └── sympy__sympy-20590/
                            ├── report.json
                            ├── run_instance.log
                            ├── test_output.txt
                            └── patch.diff
```

See the [official evaluation guide](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/evaluation.md) for grading details.
